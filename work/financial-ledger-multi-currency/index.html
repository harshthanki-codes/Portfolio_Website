01//PROBLEM & CONSTRAINTS

The Technical Challenge

Real enterprise limitations, legacy constraints, and boundary conditions.

Core Operational Bottleneck

Project-based manufacturing operations require live multi-currency cost tracking (raw materials, contracted labor, machinery overhead) tied to volatile FX exchange rates and thousands of split invoices.

Architectural Constraints

Synchronous external FX rate API lookups were freezing client UI sessions for up to 4.2 seconds, and computed fields triggered severe N+1 query cascades across massive relational timesheet tables.

03//ENGINEERING DECISIONS

Key Architectural Decisions & Trade-Offs

Why specific choices were made and why common alternatives were rejected.

Decision: In-Memory Daily FX Snapshot Cache with Fallback Stored Rate Matrix

Rationale: Eliminated synchronous external HTTP requests during user transaction commits, cutting write latency from 4,200ms to <12ms.

Rejected Alternative: Live per-transaction external API fetching
Reason for Rejection: Subjected production transaction commit locks to third-party network jitter and API downtime.
Decision: Compound Database Indexing & Batch Pre-aggregation

Rationale: Replaced calculated Python property methods with indexed SQL view rollups, eliminating N+1 query cascades across 50,000+ line items.

Rejected Alternative: Client-side calculation in browser JavaScript
Reason for Rejection: Massive payload sizes (>12MB raw JSON) caused browser tab crashes on mobile devices.

06//FAILURE MODES

Edge Cases & Production Lessons

Real failure modes encountered during load testing and how they were remediated.

Incident / Failure: Floating point rounding discrepancies across dual-currency conversions

Root Cause: Standard Python float calculations produced IEEE-754 precision drift on fractional cents.

Architectural Resolution: Enforced Python `decimal.Decimal` with explicit `ROUND_HALF_UP` quantization across all transaction paths.
